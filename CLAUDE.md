# CLAUDE.md — Invoice Rescue

## Production D1 workflow

Schema lives in `backend/db/migrations/*.sql`, tracked via `wrangler d1 migrations` (no more ad-hoc `d1 execute --file=...`). To change the schema: `npx wrangler d1 migrations create invoice-rescue-db <name>`, edit the generated file, verify with `npx wrangler d1 migrations apply invoice-rescue-db --local` (wipes `.wrangler/state` first if you want a truly clean test), then apply for real with `--remote`. D1/wrangler has no automatic "down" migration — to roll back, write and apply a new forward migration that undoes the change; since SQLite can't `ALTER TABLE DROP CONSTRAINT`, undoing a CHECK-constraint migration means rebuilding the table again (see `0003_add_check_constraints.sql` for the rename/create/copy/drop pattern used here). Beyond that, D1 has automatic **Time Travel** for point-in-time recovery — no setup required, `npx wrangler d1 time-travel restore invoice-rescue-db --bookmark=<bookmark>` or `--timestamp=<ISO8601>` — plus manual snapshots via `npx wrangler d1 export invoice-rescue-db --remote --output=backup.sql`. Secrets (`GEMINI_API_KEY`, `STRIPE_SECRET_KEY`) belong in Cloudflare's secret store via `npx wrangler secret put <NAME>`, never in `wrangler.jsonc` vars or anything committed; `.dev.vars` (gitignored) holds local-dev copies only.

## Known gaps (as of 2026-07-28)

- **Deploy token is under-scoped.** The `CLOUDFLARE_API_TOKEN`/`CF_ACCOUNT_ID` env vars the local `wrangler` CLI reads can list D1 databases but fail with `Authentication error [code: 10000]` on Workers Scripts endpoints — both `wrangler deploy` and `wrangler secret put` fail. As a result, **production is currently running Worker code older than `backend/src/index.ts`** (missing the `POST /api/clients` route at minimum — diff the deployed bundle against source before assuming they match). Fix: grant the token `Workers Scripts:Edit` at dash.cloudflare.com/`<account>`/api-tokens, or run `wrangler login` once for a browser-authenticated session — then `npx wrangler deploy` and set the two secrets.
- **`/admin`, `/api/chase/*`, and `/api/clients` have no auth.** Put Cloudflare Access in front of all three before real client/debtor data flows through them (docs/credit-control-system-design.md §4.4).
